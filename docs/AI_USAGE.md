## 实际使用

开发使用 Codex 协助阅读题目、收敛交互、编写 React / TypeScript 页面、实现规则引擎、检索接口文档、抓取并复现公开数据、编写测试和交付文档。工作按界面、确定性引擎、数据溯源、服务端适配器分工，再由主流程集成验证。

当前默认产品运行时使用显式规则解析器，没有真实模型 API 调用记录，也没有假造模型接入成功状态。通用兼容模型适配器已实现，需在服务端同时配置 AI_API_KEY、AI_BASE_URL、AI_MODEL 后才会在用户提交描述时调用。无配置返回 mode: rules；配置检查不代表连接成功。模型分支通过 mock 测试，但尚未验证用户服务的实际协议兼容性、权限与效果，不能声称支持任意自由文本金融推理。

## AI 辅助实现中的技术纠正

| 易出现的错误或不合理结果 | 本次处理 | 可验证证据 |
| --- | --- | --- |
| 把文档 URL 当作账号权限，宣称已接实时行情 | 无 key 不发请求，明确返回 503 与未配置说明 | `app/api/data/route.ts`；missing credential 测试 |
| 把 HTTP 200 当作业务成功 | 同时检查 `code===0`，非 0 显式失败 | `lib/providers.ts`；business status 测试 |
| 把“净利润同比”直接写成“归母净利润同比” | 不做无依据映射，保存原始字段，`profitGrowth=null` | 财务官方文档；provider 口径测试 |
| 把“营业收入”和“营业总收入”混为同一指标 | 保留口径差异，未确认映射时 `revenueGrowth=null` | 历史 `YSTZ` 字段与扶摇文档逐项比较 |
| 负 PE 小于 30 就算“便宜” | 标为估值指标不适用，不能判为通过 | 筛选引擎边界测试 |
| 财报按报告期回填后仍自称是当年可用数据 | 明确当前可得历史数据，`isPointInTime=false` | `data/snapshot.json`、原始财报 `UPDATE_DATE` |
| 空字符串或 `null` 转成 0 | 只接受有限数字，空缺保留未知 | `parseFiniteMetric` 测试 |
| AI 自动理解模糊词并给确定结论 | 默认阈值可见并要求确认；无法支持的内容显式披露 | 规则解析结果的 `clarifications` / `unsupported` |
| 用人工编造数值来方便演示 | 默认数值来自保存的公开源响应；异常用测试模拟 | `data/raw/manifest.json` 与复现脚本 |

## 职责边界

1. 规则解析器把支持的用户表达转成有限指标、`gte/lte` 运算符和数字；未知描述不静默忽略。模糊阈值属于待用户确认的操作化方案，不是金融事实。
2. 确定性引擎检查条件冲突并逐项执行，返回通过、失败、数据未知。解释必须和同一组数值比较一致。
3. 数据层负责来源、时间、单位、缺失及错误。原始数据不由生成模型“补全”。
4. 可选模型分支只负责意图转译，不得生成行情、决定个股入选、预测收益或绕过条件校验。实现了严格字段白名单、15 秒超时和显式规则回退；模型自由文本先检查危险内容，再替换为服务端模板，界面只呈现根据允许指标及数值生成的确认说明；需要真实账号联调与模型输出评测后才能称为已验证接入。

## 验证证据及其限度

单元测试使用明确合成样例和 mock 响应验证错误分支，不冒充真实联网测试。实际公开数据来自保存的 14 份请求响应，离线复现检查哈希和指标计算；同花顺公司年报做了一个独立原文抽查，未逐份审计全部公司年报。扶摇适配器按官方接口合同实现，未用用户账号做认证或额度验证。

完整的执行命令与验收场景见 [测试说明](TEST_PLAN.md)。真实可访问的部署地址及是否完成浏览器验收，须以最终交付记录为准。
